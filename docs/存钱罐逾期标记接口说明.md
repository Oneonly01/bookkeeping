# 存钱罐逾期标记接口说明

## 判断规则

- 目标未删除、原状态为 `active`，且截止日期早于服务器的今天时，判为逾期。
- 截止当天不算逾期；未设置截止日期、已暂停、已完成的目标不标记逾期。
- 逾期天数按 Django 当前时区的自然日计算。正常部署使用 Asia/Shanghai 时区。
- 逾期是动态展示标记，数据库原状态仍为 `active`，不新增数据库状态，不需要迁移或定时任务。
- 延长截止日期至今天或未来、清空截止日期、暂停、完成目标后，标记自动消失。恢复已过期的暂停目标后，重新显示逾期。
- 逾期不冻结资金操作。原有存入、取出、暂停、恢复、完成、删除和账户余额处理规则保持不变。

## 目标响应新增字段

列表、详情、创建、修改、暂停、恢复接口返回的目标，以及存入和取出响应中的 `data.goal`，均增加以下只读字段：

```json
{
  "status": "active",
  "status_display": "进行中",
  "is_overdue": true,
  "overdue_days": 3,
  "display_status": "overdue",
  "display_status_text": "已逾期"
}
```

| 字段 | 含义 |
| --- | --- |
| status / status_display | 保留原业务状态和中文描述，兼容现有调用 |
| is_overdue | 是否逾期，布尔值 |
| overdue_days | 逾期自然日数，未逾期为 0 |
| display_status | 展示状态：active、paused、completed、overdue |
| display_status_text | 展示文案：进行中、已暂停、已完成、已逾期 |

前端展示状态标签和逾期提示时，可直接读取新增字段，不必自行用浏览器日期重复判断。操作权限仍结合原业务状态与原有接口规则处理。新增字段不接受客户端写入，不能通过提交 `status=overdue` 修改目标。

## 列表筛选

需要登录，继续使用原有 Bearer Token。

```http
GET /api/v1/savings/goals/
GET /api/v1/savings/goals/?status=overdue
GET /api/v1/savings/goals/?status=active
GET /api/v1/savings/goals/?status=paused
GET /api/v1/savings/goals/?status=completed
```

不传 `status` 返回当前用户全部未删除目标，仍为数组，按创建时间、ID倒序排列。

`overdue` 只返回逾期进行中的目标；`active` 只返回**未逾期**进行中的目标；暂停、完成分别按原状态筛选。无效状态返回 HTTP 400。其他用户或已删除目标不包含在任何结果中。

## 汇总新增字段

- `GET /api/v1/savings/summary/`：`data.overdue_count`。
- `GET /api/v1/dashboard/summary/`：`data.savings.overdue_count`。

注意：为兼容已有前端，两个接口的 `active_count` 仍包含逾期进行中的目标。`overdue_count` 是 `active_count` 的子集，不能再与三个原状态数量相加作为总数。

前端互斥标签数量可使用：进行中 = `active_count - overdue_count`；已逾期 = `overdue_count`；暂停、完成数量不变。

## 部署与验证

本次无数据库字段变更，无需运行迁移；更新代码后重新构建并启动后端服务即可。前端未改动，接入新增字段后可统一采用服务器的逾期判断。

独立测试命令（使用内存 SQLite，不连接开发 MySQL）：

```bash
python manage.py test apps.savings.test_overdue --settings=config.test_settings
```
