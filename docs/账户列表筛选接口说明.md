# 账户列表筛选接口

## 请求

`GET /api/v1/accounts/`

请求头：`Authorization: Bearer <access_token>`。
Query参数如下；不传参数时保持原有行为，返回当前用户全部未删除账户，包括停用账户。

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `keyword` | string | 否 | 账户名称模糊搜索，最多50个字符，自动删除首尾空格 |
| `account_type` | string | 否 | 具体账户类型 |
| `is_active` | boolean | 否 | `true`启用，`false`停用 |
| `is_default` | boolean | 否 | `true`默认账户，`false`非默认账户 |

账户类型：`cash`现金、`wechat`微信、`alipay`支付宝、`bank`储蓄卡、`credit_card`信用卡、`other`其他。
这里的`bank`仅匹配储蓄卡，首页“银行卡”汇总分组则同时包含储蓄卡和信用卡。

## 示例

```http
GET /api/v1/accounts/?keyword=建设&account_type=bank&is_active=true
```

查询名称包含“建设”的启用储蓄卡，多个条件按AND取交集。

```http
GET /api/v1/accounts/?is_active=false
GET /api/v1/accounts/?is_default=true
GET /api/v1/accounts/?is_default=false
```

分别查询停用账户、默认账户、非默认账户。

## 返回及边界规则

- 沿用原有响应结构，`data`仍然为账户数组，不增加分页层。
- 排序仍按`sort_order`、`id`升序。
- 没有匹配账户时返回成功，`data`为`[]`。
- 账户类型或布尔值不合法时返回HTTP 400，并使用现有统一错误结构。
- `keyword`为空或只有空格时，不按名称筛选。
- 状态、类型选择“全部”或点击重置时，不传对应参数；不要传空字符串或`null`。
- 前端建议发送字符串`true`、`false`。例如`is_active=false`是有效筛选条件，不能因为值为false就丢弃。
- 用户身份只取自登录凭证，任何参数都不能查询其他用户或已删除账户。
- 该查询不会修改账户、余额或月末快照。
- 账户创建及其它接口参数保持原样，本次没有数据库模型变更，不需要新增迁移。

## 前端对接

可增加账户名称搜索框、账户类型选择、启用状态选择和默认状态选择。
查询时发送选中条件；重置时移除条件，再请求原地址。
顶部总资产概览仍由资产概览接口独立提供，不因账户列表筛选而变成筛选结果的小计。
