# 存钱罐列表搜索筛选接口说明

## 请求方式

`GET /api/v1/savings/goals/`

携带原有 `Authorization: Bearer <access_token>`，参数填写在 Apifox 的 Query 参数中，不放在 JSON 请求体中。

## 查询参数

所有参数均为选填，多个条件同时传入时取交集。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| keyword | string | 目标名称或备注的模糊搜索，去除首尾空格，最多100个字符，空字符串不筛选 |
| status | string | active：未逾期进行中；overdue：已逾期；paused：已暂停；completed：已完成；查询全部时不传 |
| min_target_amount | decimal | 目标金额下限，包含边界 |
| max_target_amount | decimal | 目标金额上限，包含边界 |
| min_current_amount | decimal | 当前已存金额下限，包含边界 |
| max_current_amount | decimal | 当前已存金额上限，包含边界，0可查询尚未存钱的目标 |
| deadline_start | date | 目标截止日期下限，包含当天，格式YYYY-MM-DD |
| deadline_end | date | 目标截止日期上限，包含当天，格式YYYY-MM-DD |

金额非负，最多14位数字（含最多2位小数）。支持只传下限或只传上限。金额不允许负数、非法字符、超限数字或超过2位小数；下限不能大于上限，日期起点不能晚于终点；错误返回HTTP 400。

只要传入截止日期范围，就不会返回没有截止日期的目标；此范围指目标的截止日期，不是创建日期。未填写的金额、状态、日期参数应直接省略，不要传空字符串。

## Apifox示例

搜索名称或备注包含“旅行”的所有未删除目标：

```http
GET /api/v1/savings/goals/?keyword=旅行
```

搜索未逾期、目标金额3000至10000元、已存不超过1000元的旅行目标：

```http
GET /api/v1/savings/goals/?keyword=旅行&status=active&min_target_amount=3000&max_target_amount=10000&max_current_amount=1000
```

查询11月到期的目标（包括已暂停、已完成目标，仍需结合status按需筛选）：

```http
GET /api/v1/savings/goals/?deadline_start=2026-11-01&deadline_end=2026-11-30
```

查询尚未存钱的逾期目标：

```http
GET /api/v1/savings/goals/?status=overdue&max_current_amount=0
```

## 返回和接入说明

- 返回结构保持原有`code/message/data`，`data`仍为目标数组，不改为分页对象。
- 无匹配结果返回`data: []`。不传查询条件返回当前用户全部未删除目标，继续按创建时间、ID倒序。
- 列表筛选不会修改目标或影响储蓄汇总、首页汇总；其他用户和已删除目标始终被排除。
- 本次增加后端查询能力，前端当前搜索栏和状态标签仍在已加载列表中筛选；金额和日期筛选控件需要前端另行接入上述参数。首页及现有不传参数的调用保持原行为。
- 无数据库字段变化，无需迁移。更新后端代码并重建启动Docker服务后可在Apifox测试。
